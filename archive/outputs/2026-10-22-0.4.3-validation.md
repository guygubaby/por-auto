# Por Auto 0.4.3 审查与验证

范围：main 上本轮全部未提交改动，包括持续等待、启动复位、精简记录、HTTP JavaScript 处理、现有界面组件和发布版本。

## Standards

按 Code Review 技能并行审查仓库规则和实际调用链，未发现未修复的规范问题；沿用 Go、React、pnpm、原生无障碍和共享脚本。没有新增运行时依赖或重试框架。

## Spec

已修复审查发现的问题：

- 慢列表的旧画面可能被当作列表末尾；现在传播原生滚动结果，并等待成功滚动后的列表变化。
- 启动过慢时可能按返回退出应用；现在等待可识别的导航。搜索页关闭键盘后仍需返回的情况，按原生节点变化判断，不只比较页面名称。
- 手动取消后的清理可能无限等待；任务等待没有固定时限，设备服务清理和设置恢复有独立的退出限制。账号验证检查移到公共读树路径。
- 取消后仍能保存简要失败结果；部分完成数量继续返回桌面，并在结束回调前更新。
- 历史清理与完成写入互斥，终态元数据最后写入；损坏历史不会阻止启动，清理使用实际目录标识，保护运行中记录。
- 手机导出从保留历史读取，并匹配来源和分支；诊断写入失败仍保留原始终态与错误。

## 验证

- `go test ./internal/...`：通过，包括卡顿恢复、取消、200 条保留、损坏历史和失败诊断大小回归。
- `pnpm test:mobile`：56 项通过，包括 1000 个会话、延迟滚动/输入/发送回查、手动停止、历史保留与导出。
- `pnpm test`：31 项通过；`pnpm build:web`：通过。
- `pnpm mobile:check`、`pnpm registry:check`、`pnpm test:updates`、`pnpm release:check --tag v0.4.3`：通过。
- Codex 浏览器确认工作流配置、HTTP 来源及 JavaScript 编辑入口正常显示。
- vivo X21 / 企业微信 5.0.12：从通知栏拉下启动、读取姓名、打开首个会话、从任务管理界面启动、测试群草稿输入/回读/清理均通过。全部为预演，没有点击发送；键盘和常亮设置均恢复。
- 实测成功记录只有 3 个小 JSON 文件，每条约 1.0～1.3 KiB；无页面、服务或事件日志。1000 个对象的预演不逐个重写历史，只保留数量。

## 发布与边界

- 桌面 0.4.3；手机包 1.0.16 / versionCode 62；启动器协议 2。
- 历史最多 200 条。成功只留摘要，失败额外保留最近 32 条事件、最多 32 KiB 页面证据和最多 32 KiB 服务日志。旧格式仍兼容读取。
- 手机包升级需先重新导入新版启动器；旧定时任务保留旧快照，需要重新创建才能使用新版业务逻辑。
