# 一台电脑管理多台 Android 手机：微信群转发群控方案

更新日期：2026-10-15，Asia/Shanghai。最新需求：一台电脑作为中控，管理多台 Android 真机，集中配置、定时执行并查看各手机的微信群转发结果。

**推荐组合：ADB 连接多台手机，uiautomator2 按设备分别操作微信，scrcpy 或其图形客户端用于查看和人工接管。业务任务由电脑统一调度。每台手机不必再单独开发一个业务 App，也不强制安装 AutoJs6；自动化框架仍需部署必要的设备端组件。**

以下主方案按电脑与手机集中部署或位于可稳定连接的局域网设计；异地分散手机见第 7 节。本文是实现方案与源码调研，不是已经运行的群控产品。

## 1. 先区分两种群控

| 类型 | 实际能力 | 对本需求的用途 |
| --- | --- | --- |
| 同步操作 | 主控手机的点击、输入等操作同步到其他手机 | 适合界面一致时批量设置；各手机页面或加载进度不一致时，不能保证相同操作产生相同结果 |
| 独立任务调度 | 下发同一业务目标，各手机读取自己的页面、群清单和进度，独立完成操作 | **微信群转发的主方案**；允许每台手机的群和执行速度不同 |

客户需要的核心是统一安排任务、分别完成并汇总结果。同步点击可作为人工辅助，但不能代替群识别、卡片定位和发送核验。

## 2. 推荐架构

```text
电脑中控：设备列表、素材/源群规则、目标分配、时间、进度
                               ↓
                  本地持久化任务记录与调度
                 ↙              ↓              ↘
           手机 A 执行器    手机 B 执行器    手机 C 执行器
                 ↓              ↓              ↓
          uiautomator2     uiautomator2     uiautomator2
                 ↓              ↓              ↓
             ADB/USB         ADB/USB         ADB/USB
                 ↓              ↓              ↓
           微信账号 A      微信账号 B      微信账号 C

scrcpy / 图形客户端：按需查看某台手机，暂停自动任务后人工接管
```

uiautomator2 文档明确支持按 ADB 序列号连接设备；多台设备时必须明确指定设备，不能依赖默认连接 [1]。scrcpy 同样支持按序列号选择设备、USB 或 TCP/IP 连接 [2]。

一台手机对应一个独占执行器，电脑可以同时运行多个设备执行器。每个执行器独立等待界面、处理异常；一台掉线时只暂停该台，不阻塞其他手机。具体并发数由容量验证确定。

首版可先使用现成投屏界面配合本地任务工具验证，不先开发大型管理平台。客户确认需要图形中控后，再实现最小的设备列表、任务配置和结果页；本次不创建或自动选定新的 Web 项目技术栈。

这些项目不是已经适配当前微信的通用群发成品。完整的开源能力、发布快照和代码边界见 `../work/phone-fleet-source-findings.md`。

Stars 是本次查询快照。QtScrcpy 的按键映射/点击序列不等于日历任务和微信状态机；STF 的定时预约也不等于定时执行微信群转发。若选择现成软件采购或二开，应按实际交付功能验收。

## 4. 微信任务怎样分配

### 4.1 一个账号对应它能访问的群

录入“设备 → 当前微信账号 → 可访问的目标群”的映射，给目标分配业务侧唯一标识。每轮任务按这份确认的清单分配，不假定一个账号可同时登录多台 Android 手机。

同一个群可能被多个账号访问。若客户要求每个目标群每轮只收到一份，清单中应指定该群的唯一执行账号；任务去重键应包含轮次与目标，而不能仅按设备去重。UI 自动化不能凭群名推导跨账号的稳定群 ID，跨账号重名群仍需客户确认归属。

### 4.2 普通链接与卡片的分发方式不同

- **文字 URL：** 可以由指定素材手机读取一次，电脑固定完整原文，再分给其他设备执行器发送。保留全部查询参数，不擅自改写推广链接。
- **原生网页/小程序卡片：** 电脑不能把截图或文字标题当成可恢复的微信卡片对象。优先让各执行账号都能访问素材源群，各自定位同一条原始消息后原生转发；若做不到，必须验证其他明确的素材流转路径。

每轮先固定素材条件、原文或定位证据，再执行。不能在长任务中不断改取源群最新消息，导致不同目标收到不同素材。

### 4.3 一台手机一个串行队列，多台之间并行

各手机独立执行“定位目标 → 核对身份 → 输入或转发 → 回读结果”。同名群或源消息不明确时暂停该目标。每台手机只接受一个占用微信界面的任务；人工接管前也要暂停该执行器。

任务记录至少区分待执行、发送前失败、发送动作已开始、界面观察成功、结果不确定。发送动作前先落盘；发送后断开时先核对，不直接重发。界面观察成功不能证明对端已读，也不是服务端送达回执。

## 5. 手机怎样连接电脑

首版建议使用稳定的 USB 数据连接，逐台开启开发者选项、USB 调试，并在手机上授权该电脑。Android 官方 ADB 文档说明了 USB 与无线连接方式 [7]。

手机较多时需要能传输数据的 USB Hub、合适的数据线及供电。只有充电功能的多口充电器不能承担 ADB 连接。USB 拓扑、主机控制器、Hub、线材和手机端接口都会影响实际稳定性。

局域网无线连接可作为备选，但配对、重连、IP 变化、无线带宽需要验证。若客户的手机分散在异地，不按这套本地 USB 方案直接报价。

首次接入与调试授权仍需要在各手机上完成；手机需要保持微信登录和可操作状态。密码锁屏时需用户解锁，自动执行期间占用手机前台。

## 6. 一台电脑能带多少台

不在没有主机、连接拓扑和实测数据时承诺“固定能带 50/100 台”。要分开测量：

1. 能稳定在线的手机数：连接、供电、掉线重连。
2. 能同时操作的手机数：CPU、内存、设备响应和任务资源占用。
3. 能同时流畅投屏的手机数：还受编码/解码、分辨率、帧率、USB/网络带宽影响。

同时自动执行和同时显示全部高清画面是不同负载。中控默认显示状态和按需缩略图，需要排障时再打开选中手机的投屏；scrcpy 官方支持调节分辨率、帧率与码率 [3]。不要默认把多种投屏客户端同时连接同一设备，需要验证与任务执行器能否共存。

建议先用 **1 台电脑 + 3 台实际手机** 验证独立并行，再按客户计划数量分批扩容。3 台只是验证起点，不代表容量上限或已经测得的性能。

此前每群 15–30 秒的估算仍只是待验证假设。多设备的理想速度受各账号实际分配群数影响，应按最慢设备的任务完成时间评估整轮窗口，不能简单按手机数量等比分摊。

## 7. 何时继续采用 AutoJs6

如果希望任务下发后，即使电脑断开，手机也能按本地计划继续执行，可以改成“电脑中控 + 每台手机 AutoJs6 执行脚本”。此时需要任务传输、设备身份、心跳、版本管理和结果回传，属于另一条交付范围。

AutoJs6 官方 VSCode 扩展已有向所有已连接设备运行/停止脚本、向指定设备运行及保存脚本等功能，可以用于开发阶段的多设备验证 [8]。它是开发工具，不等于已经具备面向客户的业务任务平台。

若手机分散在异地，通常需设备端执行器主动连接任务服务，并提供相应管理入口；应单独确认网络、部署和服务范围。本地集中真机首版优先采用 uiautomator2 路线，以减少设备端业务 App 的开发。

## 8. 首版范围与验收

最小交付范围：设备发现与别名、账号/目标群分配、素材规则、定时任务、按设备启停、任务持久化、结果汇总、失败截图和按需人工接管。

验证至少覆盖：

1. 三台手机各自处理不同目标群，某台页面加载慢时其他设备继续执行。
2. 拔掉一台手机连接，其任务进入暂停/待核对，其他设备不受影响。
3. 点击发送后断开及电脑重启后恢复，不直接重发结果不确定的目标。
4. 普通链接保持完整；卡片在每个执行账号上能找到同一原消息并转发。
5. 定时重复触发、过期任务、账号/群映射错误和人工接管均有明确处理结果。

**报价变化：** 此前 9,000–15,000 元是纯手机运行器、脚本与简单配置页的估算，不涵盖电脑群控中台。群控应重新确定电脑系统、手机数量和型号、同时执行数量、是否异地、是否要求断开电脑后继续运行，以及管理界面范围，再估工期。可以先单独签三台手机的验证，不凭一个“群控”词就固定包价。
