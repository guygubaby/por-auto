# 原生输入组件与微信流程验收

环境：vivo X21 / Android 9 / 微信 8.0.79 / 官方 AutoJs6 6.7.0。
本轮发送类流程均为预演，没有点击发送，未验证消息实际送达。

## 已确认

- 原生输入组件采用 Kotlin InputMethodService 和受校验的本地 ContentProvider；无网络权限、无截图或 OCR。优化并签名后的 APK 为 29,360 字节。调用方仅限已授权 ADB shell、组件自身和固定官方证书的 AutoJs6。
- 原生中文搜索、输入 1、完整回读、拒绝覆盖已有草稿、只清理本轮相同草稿均已通过。系统键盘选择器通过原生标签和行边界定位，无模型参与；切换并恢复日常键盘的闭环通过。
- 手机真实商店与 Cron 快照入口：打开微信、读取昵称、首个会话通过；文件传输助手完整预演通过，执行后原键盘恢复。页面导航使用用户指定的图像模型；文字值由原生接口回读。
- 批量流程已完整枚举当前 12 个群；已完成其中 4 个群的输入、回读和清理。语音模式会先独立核对底部输入栏，再切回文字模式。其余群聊验收仍在进行。
- 定位并修复前台判断问题：AutoJs6 的事件缓存包名可能属于输入法，实际焦点应用仍是微信；运行器改读系统窗口信息，模态窗口阻止继续操作。
- 顶部入口由原生窗口尺寸确定，模型只确认局部工具栏，页面切换只重新观察、不重放点击；不再依赖整页模型坐标或粘贴菜单。

## 边界

桌面原生输入协议、恢复与传输校验已通过自动测试，最新桌面真机流程、完整群聊、手机 HTTP 定时回归和 Windows 安装包仍需完成。千会话逻辑测试不代表千群真机性能验收。正式发送及网络送达未测试。
