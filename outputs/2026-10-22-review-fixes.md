# 企业微信-only 代码审查修复记录

日期：2026-10-22（Asia/Shanghai）。本轮修改 `main` 并发布 `0.4.1`；未改变既有用户数据目录。MyGo 更新签名公钥按迁移后的独立密钥体系更新。

## 支持范围

只支持企业微信 `com.tencent.wework`，不再支持普通微信读取或发送。桌面旧微信工作流不会出现在安装列表，其定时任务暂停；残留普通微信原生页面、会话列表与 Go 输入执行分支已删除或拒绝。历史日志继续只读查看、导出，不自动删除用户数据。

手机目录和离线包只发布无害示例 `demo-hello` 与企业微信业务包 `wecom-suite`。当前企微包为 `1.0.12 / versionCode 58`。历史来源中已安装的普通微信脚本不属于当前支持范围，应停用其任务并删除旧安装，不继续适配。

## 九项修复

| 审查项 | 修复 | 回归依据 |
| --- | --- | --- |
| 1. 手机入口工厂不匹配 | 原生适配器按函数调用共享 IO，不再访问不存在的 `.create` | 加载真实发布目录的入口、适配器和 IO，进入菜单及校验定时入口 |
| 2. 重复发送步骤 | 桌面、手机与索引共用严格字段、动作参数和 Schema 校验，最多一个发送动作 | 重复固定发送、重复批量发送、未知字段、无效参数和 Schema 被拒绝；控制器在 Hook/设备 IO 前停止 |
| 3. 模糊目标标题 | 去掉省略号补全和数字前缀删除；只接受完整名称及群成员数后缀 | 相似名称在确认、草稿核对与提交前被拒绝，未输入、未点击发送 |
| 4. 卸载绕过 | 启用、编辑为启用、立即运行、Cron、重启恢复及执行器检查安装状态；已领取批次阻止卸载 | 旧快照不能产生设备执行记录，原版本/配置保留 |
| 5. 升级凭据失效 | 保留历史企业微信 Keystore alias，不重新生成另一把密钥读取旧密文 | 用历史 alias 的 AES-GCM 密文测试真实 IO 解密与地址绑定 |
| 6. 收发方向混淆 | 企业微信 5.0.12 映射增加消息行 `ixq` 与头像 `j3b`，只有同一行的唯一右侧头像可确认 outgoing | Go/手机分别覆盖短消息、跨中线长消息、收到消息、头像缺失/重复及错位 |
| 7. ID 决定配置能力 | React 统一按 `chat_broadcast` 动作识别批量配置 | `daily-report` 能展示并保存消息/接收配置；名称含 broadcast 的普通流程不被误判 |
| 8. HTTP 正文不同步 | POST/PUT/PATCH 切换保留正文，GET/DELETE 清空；提交值变化时重置文本框，保留未提交的无效 JSON | 核对可见 JSON 和实际测试请求，覆盖正文方法切换与空正文重建；更改地址/鉴权类型清除密钥草稿 |
| 9. 缺失差分文件 | `mygo.json` 显式设置 `updates.deltas: 0` | 发布回归约束该配置，继续校验完整归档、平台数量、版本与签名 |

工作流索引的 `registry:check` 同时修正为只校验、不写回。HTTP JSON Schema 与文档同步为 GET/POST/PUT/PATCH/DELETE、5～120 秒，GET/DELETE 不发送正文。

## 升级与验收边界

1. 手机普通运行更新到包 58 后采用新代码；旧手机定时任务固定旧版本代码，需要停用后重新创建任务才能采用本轮修复。不会静默替换用户批准过的快照。
2. 桌面保持 `com.por.wechatreader` 数据目录与系统凭据服务名；手机继续使用 `com.por.autojs6.wechat.credentials.v1` 历史 alias。这些标识用于数据兼容，不代表恢复普通微信支持。
3. 本轮未做手机真机发送、长时间手机定时、Windows 实机或系统 WebView 交互验收；模拟环境通过不能替代这些检查。新消息方向映射仍需在目标设备上重新验证，UI 回读不等于收件人设备收到。
4. 本轮已重新生成手机离线制品与桌面嵌入资源，没有重新打包或发布 macOS/Windows 安装器。已有安装器与 [此前真机发送记录](2026-10-22-native-only-validation.md) 均不代表当前修复版本已通过真机验收。
