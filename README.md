# por-auto

MyGo + 系统 WebView + Go 的 Android 自动化桌面工具。前端使用 React 19、TypeScript、Vite 8、Tailwind CSS v4、shadcn/ui、TanStack Router / Query、Zustand、React Hook Form + Zod 与 Motion。界面使用白色或中性黑灰底色，浅紫色仅作为按钮、选中标记和焦点的强调色；支持浅色、深色、实时跟随系统，主题选择会保存在本机。已应用 shadcn preset `b2h2bVtx6G`；历史记录、对象结果和日志分页显示，日志按需展开。当前提供手机环境初始化、ADB 设备发现、多手机工作流执行、原生无障碍页面读取、GitHub 工作流商店和本地 Cron 定时任务。

**不需要后端服务。** 桌面 Go 代码直接连接手机及 GitHub；所有配置、已安装工作流和执行结果保存在用户本地。客户无须安装 Python、Node.js、Go、Git 或 Android Studio。

**当前只支持企业微信，不支持普通微信的读取或发送。** 普通微信工作流及手机业务包不再发布，桌面残留原生执行分支也已移除；旧运行记录仍可查看和导出。当前手机企业微信包为 `1.0.12 / 58`，本轮修复与验证边界见 [代码审查修复记录](outputs/2026-10-22-review-fixes.md)。

## 客户试用

Windows 10/11 x64 安装包生成后位于 `deliverables/`。使用步骤见 [客户试用说明](deliverables/客户试用说明.md)。

1. 安装软件，首次打开点击「初始化连接组件」。ADB 随软件附带；缺少 WebView2 时由安装器联网补齐。
2. 手机开启 USB 调试、通过数据线连接，在手机上允许该电脑调试；保持解锁、企业微信已登录并使用简体中文。
3. 点击「刷新设备」，勾选一台或多台已授权手机，选择「读取企业微信姓名」并点击「开始运行」。最多同时运行 4 台，同一手机任务按到达顺序排队，一台失败不影响其他手机。
4. 软件显示步骤进度；在「运行结果」选择手机查看对应昵称、错误和逐会话结果。点击「打开结果目录」查看 JSON 与页面结构。

部分 Windows 手机需品牌官方 USB 驱动。手机端 USB 调试授权、解锁和企业微信登录需要用户完成。当前试用包没有商业代码签名证书，Windows 可能提示未知发布者。

### 原生无障碍执行

页面动作只面向企业微信，并直接读取系统无障碍节点。页面标题、导航、完整会话名称、输入框和唯一的「发送」按钮全部核对后才操作；节点缺失、控件不唯一或页面切换不明时安全停止，不推测坐标。

标题不接受省略号补全或移除名称中的数字前缀，只允许完整名称及群成员数后缀。发送回读同时确认消息行和同一行的唯一右侧头像；收到的消息不能作为发送回执。无法确认时停止后续发送，不自动重发；界面观察仍不等于网络送达。

文字通过企业微信原生编辑控件写入，并完整回读后才会发送。已有草稿、目标歧义、连接变化或未知结果均停止；不重试写入或发送。普通微信工作流和对应手机包已移除。

## 工作流商店

默认源为本仓库：`https://github.com/guygubaby/por-auto`，分支 `main`，固定读取 `workflows/registry.json`。

在软件中粘贴其他 GitHub 仓库根地址、填写分支或标签并同步，即可安装该仓库的标准工作流。私有仓库需要有访问权限的 GitHub 令牌（Contents 只读）；令牌仅用于本次同步，不保存到磁盘、不嵌入客户端。默认附带 4 个企业微信工作流，无令牌也能离线试用。

更新流程：新增或修改 `workflows/<id>/workflow.json` → `pnpm registry:index` → 提交并推送 → 客户在商店刷新并安装更新。已安装版本不会被目录刷新直接替换；工作流使用现有引擎动作时无需重新发布软件。

完整格式、支持动作、限制和目录约定见 [工作流开发说明](workflows/README.md)。当前附带 `wecom-open`、`wecom-nickname`、`wecom-first-chat` 和 `wecom-broadcast`。

## 企业微信原生工作流

企业微信提供 `wecom-open`、`wecom-nickname`、`wecom-first-chat`、`wecom-broadcast` 四个工作流；批量发送使用引擎 5，按单聊 / 群聊分类处理全部对象，支持手动/HTTP 消息、前后置请求、预演和本地 Cron。电脑端和手机端都直接读取原生组件，无需 OCR 或图像模型。

原生控件采用版本映射；Go 桌面宿主已在 vivo X21 / 企业微信 5.0.12 通过四个流程预演和真实分钟 Cron / HTTP 检查，中文输入、回读与清理正常。本次移除普通微信工作流后的范围与验收边界见 [原生无障碍验收](outputs/2026-10-22-native-only-validation.md)。

手机商店安装「企业微信手机工作流」即可独立运行。发布脚本把共享 HTTP、消息校验、结果记录和生命周期逻辑生成到企微包的真实目录，线上与离线安装使用同一份校验清单；修改共享代码时需增加 `wecom-suite` 的 `versionCode`。原生任务不需要截图授权。

手机更新保留配置和加密凭据，继续使用旧企业微信包的 Keystore 标识，避免更名导致旧密文无法解密。已有手机定时任务固定旧脚本版本，更新业务包后需重新创建任务才能采用本轮修复；不会静默替换已批准的快照。

桌面连接组件为官方 uiautomator2 0.4.0 加一个小型原生节点补丁，不改变官方 JAR；补丁增加提示状态、交互窗口标志，并保留不可见容器下的可见后代节点。源码、固定上游提交和构建方法见 `native/u2-hint/`。系统提示语和真实草稿通过原生标志区分，即使用户草稿恰好等于提示语也不覆盖。

## AutoJs6 手机脚本更新

手机可使用官方 AutoJs6 6.7.0+ 独立运行 JS。导入 [工作流商店](mobile/autojs6/bootstrap.js) 后，以卡片查看、搜索、安装、更新、运行和删除工作流，也可导入离线包。默认来源是本仓库的 `mobile-workflows/registry.json`，支持切换分支和私有仓库。刷新目录只展示新版本，点击更新后才替换脚本；配置和日志保留。商店内置不操作目标应用的测试示例，业务脚本更新不需要重新安装 AutoJs6 或 PC 软件；早期菜单版入口重新导入一次即可使用商店界面。

手机目录只发布「企业微信手机工作流」业务包，复用桌面的四个工作流定义，提供消息输入、单聊 / 群聊分类、HTTP 测试与字段提取、每轮或每个对象获取最新内容、前后置请求，以及逐个对象的 JSON 结果。默认预演，填入并核对后清理草稿，不点击发送；正式运行需单独选择。该运行器只读取 AutoJs6 无障碍节点，不申请截图，也不使用图像模型或 API Key。

手机定时执行已有预览实现：在工作流菜单新建五段 Cron 任务，固定版本、消息/接收配置和 IANA 时区；在商店「更多」开启执行会话，支持启停、改时间、立即运行、删除与结果导出。当前会话保持唤醒，关闭脚本或重启后需重新开启，不补跑错过的时点，忙碌/重叠时跳过，不自动重发。首次使用此功能需重新导入最新版商店；长时间真机运行尚未验收，详见 [手机定时说明](mobile-workflows/README.md#手机独立定时执行预览)。

脚本位于 `mobile-workflows/<id>/src/`。修改后增加 `workflow.json` 的 `versionCode`，执行 `pnpm mobile:bundle`、`pnpm test:mobile` 和 `pnpm mobile:check`，提交生成文件后发布。下载按单个 Git 提交固定来源，逐文件校验 SHA-256，完整写入新版本目录后原子切换；配置和日志独立保存。运行与更新互斥，失败不自动重试业务任务。

桌面端「使用指引 → 手机独立运行」可打开 AutoJs6 官方下载页、保存启动脚本和离线工作流包，再传到手机导入。构建同时生成 `deliverables/PorAuto-AutoJs6-bootstrap.js` 与 `deliverables/PorAuto-mobile-scripts.json`。私有仓库令牌仅在当前启动器会话使用。完整使用、脚本入口约定及限制见 [手机脚本说明](mobile-workflows/README.md)。目前仍需在手机安装运行环境并导入脚本，未提供 PC 一键安装或 PC→AutoJs6 任务通信。

## 消息与生命周期配置（引擎 5）

在商店已安装卡片点击「配置」：运行前可调用 HTTP 接口，执行时使用手动消息或接口解析结果，运行后可回传本次状态。HTTP 支持 GET/POST/PUT/PATCH/DELETE、查询参数、请求头、JSON、Bearer/Basic/API Key，以及文本或 JSON Pointer 解析，提供请求与离线解析测试。超时 5～120 秒，响应最多 512 KiB；仅本机地址允许 HTTP，其他业务接口要求 HTTPS。切换 POST/PUT/PATCH 保留正文，GET/DELETE 不发送正文。

HTTP 鉴权引用绑定已保存的请求地址；更换地址会清空表单里的旧鉴权，测试与保存都需要重新填写。已有工作流和 Cron 快照从本机加载时恢复原地址绑定，保留原凭据引用及配置；不会自动把旧凭据交给新地址。

批量发送只勾选接收类型：单聊、群聊或同时选择两者，自动处理相应列表中的全部对象，不再逐个选择或填写名称。群聊读取消息首页的“群聊”分类；单聊读取“全部”分类并排除群聊清单中的完整名称。两个列表合并时按完整名称去重，避免同名群被误发成单聊；同一分类内的重名会停止。支持每轮获取一次消息或逐会话取最新值；列表完整枚举后冻结名单，再逐个核对并发送。已有草稿、目标歧义、列表不完整或发送结果不明时停止。逐会话结果保存在本机，支持停止后续发送和 JSON 导出。

新安装的发送工作流默认启用「演练模式」：进入目标会话、输入并核对文字，随后清理本轮草稿，不点击企业微信发送；已有相同草稿保留原样，其他草稿不会覆盖。演练记录为 `rehearsed`，不计为已发送。HTTP 请求和前后置 Hook 仍会执行，回调可通过 `{{run.mode}}` 区分 `rehearsal` 与 `send`。演练仅适用于标准发送动作，含通用 `tap` 的工作流拒绝演练。旧范围在首次改为分类接收时默认预演，原有定时任务保留原快照；需明确更新快照后才采用新范围。

已安装工作流可以卸载；关联定时任务暂停，日志保留，重启不会重新装回。未重新安装前，旧快照不能被启用、编辑为启用状态、立即运行或由 Cron 执行；已领取的定时批次结束前不能卸载。定时任务同时固定版本、输入和 Hook 快照，更新需显式确认。协议与执行边界见 [工作流开发说明](workflows/README.md)。

Go 通过 ADB 启动官方 `android-uiautomator-server-jar` 0.4.0，并经独立端口转发调用 JSON-RPC（与 uiautomator2 Python 客户端使用相同手机端服务），不再调用 Android 的 `uiautomator dump` 命令。客户无需安装 Python，构建和运行时校验服务的固定 SHA-256，任务结束后停止服务并移除转发。上游服务在运行期间监听手机 9010 端口且没有身份认证。原生输入组件是另一个按需安装的本地 APK，不监听网络端口。

队列在 Go 中执行，同手机 FIFO、全局最多 4 台并发，手动运行和 Cron 共用。进程退出后不会恢复内存队列，也不会自动重发。当前仍未包含 scrcpy 投屏、人工接管、按设备暂停/继续或断点恢复；这不是完整群控方案已全部完成。发送状态代表输入框清空且原生界面出现本次消息正文，**不代表网络送达或对方已读**。

已在 vivo X21 / 企业微信 5.0.12 的测试群 `ajfjfjfh` 完成一次真实群发，并从发送后的原生消息节点回读确认正文存在、输入框已清空。该结果只证明发送端界面已出现消息，不证明其他成员设备已收到。

## 本地开发与打包

需要 Node.js 24、pnpm、Go 1.27.1（MyGo v0.6.0 要求）和目标平台的打包工具。客户电脑不需要开发环境。仓库已移除 Rust、Cargo、Vue 和 Tauri 构建入口；原生 Android 输入组件仍使用现有 Kotlin 实现。

```sh
pnpm install
pnpm prepare:adb macos       # Windows 包改为 windows
pnpm prepare:assets          # 校验并准备 ADB、原生输入与 uiautomator2、共享 JS 引擎
pnpm dev                    # Go 桌面壳 + React 热更新
pnpm build:web              # TypeScript 检查与 React 构建
pnpm test                   # React 状态、主题与 HTTP 编辑器
pnpm test:go                # Go 引擎、队列、定时与迁移兼容
pnpm test:mobile            # 手机入口、共享控制器、凭据兼容与更新回归
pnpm test:updates           # MyGo 更新清单验证
pnpm registry:check
pnpm build:mac              # macOS App / DMG
pnpm build:windows          # Windows x64 EXE / NSIS 安装包
```

MyGo 无需 cgo，可直接交叉编译；macOS DMG 需要在 macOS 生成，交叉构建 Windows 安装包需要本机安装 NSIS。首次准备 ADB 时下载 Google 官方固定版本，并校验散列；已有 ZIP 可通过 `POR_ADB_ARCHIVE` 复用。`pnpm exec playwright test` 验证页面、主题和紧凑布局；真正的设备动作仍需连接手机验收。

## 应用内更新与 GitHub Release

在「设置 → 软件更新」检查更新、查看版本说明、下载并重启。默认启动后及每 6 小时检查一次，可关闭自动检查；安装需用户选择，设备任务和维护期间会阻止安装。

更新采用 MyGo 的 Ed25519 签名归档和平台清单，保留仓库来源。0.4.1 起使用迁移后的 MyGo 更新密钥；此前 Tauri 版本仍需手动迁移。网络、下载或签名失败会显示错误；更新保留本机配置、定时任务和记录。0.3.x 的 Tauri 更新格式与 MyGo 不同，迁移到 0.4.x 须手动安装一次，不能把 MyGo 归档直接交给旧更新器。

当前显式设置 `updates.deltas: 0`，只发布和下载已校验的完整更新包，不在清单中引用未发布的 `.delta` 文件。以后启用差分更新时，必须先补齐差分文件的校验与发布流程。

发布时同时更新 `package.json`、`mygo.json`、`internal/automation/engine.go` 和 `CHANGELOG.md`，运行 `pnpm release:check --tag v<版本>`。CI 需要配置与公钥匹配的 `MYGO_UPDATER_PRIVATE_KEY`（MyGo 使用 Base64 Ed25519 私钥，不能直接复用旧 Tauri 密钥文件格式）。三个平台的签名归档、安装包、版本和散列全部校验通过后才发布。未配置 MyGo 密钥的本地构建仅供手动安装，不发布为正式更新。

## 源码结构

```text
src/routes/                  React 文件路由：工作台、结果、定时、记录、商店、设置、指引
src/components/              shadcn/ui 与业务界面
src/lib/                     MyGo IPC、Query、Zustand 和批次控制
internal/app/                MyGo 窗口、主题、系统对话框和更新
internal/automation/         Go ADB、原生无障碍适配器、凭据、队列、工作流和 Cron
assets/                      构建时校验、嵌入的组件和共享工作流引擎
mobile-workflows/            AutoJs6 业务与共享 JS 核心
native/                      现有 Kotlin 输入组件与 uiautomator2 无障碍节点补丁
workflows/                   标准工作流与 GitHub 索引
scripts/                     组件准备、索引、打包与校验
outputs/                     调研与验收记录
```

Windows 配置与运行记录位于 `%LOCALAPPDATA%/com.por.wechatreader/`；macOS 位于系统分配的应用用户数据目录。`workflow-store.json` 保存工作流源和安装快照，`schedules.json` 保存定时任务与执行游标，`runs/<运行ID>/` 保存结果；设备与工作流选择保存在本机 WebView 存储中。GitHub 令牌不写入上述位置。

桌面通过 goja 执行 `mobile-workflows/shared/src/core.js`，手机通过 AutoJs6 执行生成的同一份控制器；Go 和手机适配器只负责各自的原生设备能力。工作流字段、动作参数、发送次数和输入 Schema 共用该控制器的校验，下载、安装和执行前均拒绝无效定义。每个工作流最多一个发送动作；前端按动作能力展示配置，不依赖 ID 是否包含 `broadcast`。

`com.por.wechatreader` 数据目录/凭据服务名及手机历史 Keystore alias 保留是为了兼容已有数据，不代表普通微信仍受支持。共享源码修改后必须重新生成手机包和桌面嵌入资源，不手工修改生成副本。

当前只支持简体中文企业微信原生页面；页面不同、同名节点歧义、未登录或锁屏时会停止并保留节点证据。软件不会回退到截图模型或盲点。

## 运行日志与调试导出

每次执行会立即保存工作流快照和运行元数据，按步骤追加 `events.jsonl`，记录开始/完成时间、错误和原生节点状态。结束后写入 `result.json` 与桌面结果 `desktop-result.json`；进程意外退出时，已写入的日志仍保留，列表显示“未完成 / 中断”。

「运行记录」页面可查看逐步日志、多选记录、导出调试 JSON、删除所选或清空记录。删除前确认，日志与页面结构一并清理。每次导出最多 100 条，通过系统保存对话框选择文件；JSON 包含日志、错误、工作流快照/版本、Git 提交和已有页面结构，不包含 GitHub 令牌。全部操作在本机完成。

## Cron 定时任务

在「定时任务」新建任务，选择已安装工作流、一台或多台手机、五段 Cron 和 IANA 时区（默认电脑时区）。支持预览接下来的执行时间、编辑、启停、立即执行、删除和按任务查看日志。最多保存 100 个任务，每个任务最多 1000 台手机。离线手机仍保留在任务中，失败后继续处理其他设备。

| 表达式 | 执行时间（按任务时区） |
| --- | --- |
| `0 9 * * *` | 每天 09:00 |
| `0 9 * * 1-5` | 周一至周五 09:00 |
| `0 * * * *` | 每小时整点 |
| `*/30 * * * *` | 每小时的 00 和 30 分 |

格式为 `分 时 日 月 周`。支持 `*`、列表、范围、步长及月份/星期缩写，周日为 0 或 7；日与星期均受限时使用 Vixie 的 OR 语义。六段/七段、Quartz 扩展和 `@daily` 等别名不在本软件格式内。夏令时缺失时刻跳过，重复本地时刻只执行第一次。

调度器在 Go 层每秒检查一次，切页、刷新前端或最小化不影响任务；必须保持客户端运行、电脑唤醒及手机连接。退出软件后停止，重启只计算未来时点，不补跑、不自动重试。正常调度有 10 秒宽限；电脑休眠或延迟超过宽限时跳过该轮，并记录原因。同一任务不重入；不同手机最多 4 台并发，同一手机的任务排队，等待中的任务也阻止维护/更新。单设备队列最多 16 项，超过时记录失败。维护期间不启动设备任务。暂停只停止未来触发，当前批次继续完成；暂停的任务仍可手动「立即执行」。

每个任务保存完整工作流快照、版本和 Git 提交，商店更新不会静默更换任务脚本。编辑同一工作流时继续保留旧快照；如检测到已安装版本变化，可明确勾选更新快照。保存配置使用临时文件、同步落盘与原子替换；到点时先保存下一个执行游标，再启动批次，防止进程中断后重复触发。客户端启用单实例，避免多个窗口进程重复调度。

每次触发均生成批次记录，包含任务 ID、名称、触发方式、计划时点、所选手机、快照和逐设备结果链接；实际设备执行另有步骤日志和结果。跳过、部分失败也可按任务筛选、批量导出和清理。删除任务不删除历史。配置损坏会显示调度器错误并停止调度，保留原文件供排查；进程中断的任务不会自动重试。

当前没有操作系统常驻服务、自动开机启动或关机唤醒功能。给客户验收时可用 `* * * * *` 和一台测试手机确认分钟触发、最小化执行、暂停、重启不补跑与 JSON 导出，再恢复正式执行频率。
