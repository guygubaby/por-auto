# 手机工作流商店与脚本更新

手机使用官方 AutoJs6 6.7.0+，导入并运行工作流商店启动脚本。商店提供卡片列表、搜索、已安装 / 可更新筛选、安装、更新、删除和运行入口；业务 JS 按版本独立下载，不必为脚本改动重新安装 AutoJs6 或 PC 客户端。

## 客户首次使用

1. 手机安装官方 [AutoJs6](https://github.com/SuperMonster003/AutoJs6/releases/tag/v6.7.0)。
2. 按 AutoJs6 提示完成文件访问、弹窗/悬浮窗等首次设置。下载 [启动器 bootstrap.js](../mobile/autojs6/bootstrap.js)，在 AutoJs6 中打开并运行。只需这一个文件，不需要把开发源码目录一起导入。内置测试不要求无障碍权限；自动操作目标应用时，再按业务需要授权。
3. 在「手机脚本更新测试」卡片点击「运行 / 配置」。内置示例只显示“你好”，记录版本和运行次数，不打开企业微信、不发送消息。
4. 以后仍运行这个启动器：启动时读取来源目录，也可点击「刷新目录」。卡片会显示安装版本和可更新版本，点击「安装」「更新」或「全部更新」后才下载替换脚本，刷新目录不会自动替换已安装版本。

默认来源是 `https://github.com/guygubaby/por-auto` / `main`，固定读取 `mobile-workflows/registry.json`。可在「来源设置 → 设置 GitHub 仓库」修改仓库和分支；「恢复官方来源」可切回本仓库。更换来源会隔离其安装状态、配置和数据，旧来源仍保留。

私有仓库先通过「来源设置 → 输入 / 清除私有仓库令牌」填写有仓库 Contents 只读权限的 GitHub 令牌，再刷新目录。令牌输入隐藏内容，只保留本次启动器会话，退出后清除，不写入配置、业务脚本或日志。启动时尚未填写令牌，私有来源可能提示读取失败，但已有脚本仍可离线运行。

已安装卡片可点击「删除」移除脚本及其版本缓存，配置、凭据和运行日志保留；重新安装后继续使用原配置。删除后不会在下次启动时自动装回。运行与安装、更新、删除共用文件锁，避免执行期间改动脚本。

早期菜单版启动器需要重新导入一次最新版 `bootstrap.js` 才能显示商店界面；既有配置与日志保持原目录。以后的业务工作流仍直接从仓库更新，旧启动器也可继续更新兼容的业务脚本。

## 手机上的企业微信工作流

当前业务包为 `wecom-suite 1.0.17 / versionCode 63`，需要协议 3 启动器，请重新导入最新版商店脚本后更新。普通微信业务包已停止发布和支持。历史来源中仍保留的旧普通微信包不属于当前支持范围，应停用其任务并删除旧安装；不会为它继续适配读取或发送。

从来源安装「企业微信手机工作流」，或导入最新离线包。运行后可以：

1. 在「配置消息内容」选择手动文字、HTTP 接口，或前置请求的返回内容。HTTP 可配置查询参数、请求头、JSON 正文、Bearer / Basic / API Key 鉴权及 JavaScript 处理；`res` 为自动解析的 JSON 或原始字符串，使用 `return res.data.message;` 等代码返回最终消息。脚本在独立环境执行，最多 1 秒，结果必须为非空字符串且不超过 4000 UTF-8 字节；已有字段路径配置继续兼容。测试同时显示原始内容与最终解析结果。
2. 在「设置接收类型」勾选单聊、群聊或两者，自动处理所选类型的全部对象，不再填写或逐个选择名称。群聊读取消息首页的「群聊」分类；单聊读取「全部」分类并排除群聊清单中的完整名称。同一分类内重名会停止。
3. 在「前置 / 结束请求」配置开始前获取数据和结束后通知；变量沿用桌面的 {{run.mode}}、{{recipient.title}} 等形式。正式运行的 run.mode 为 send，接口测试为 preview。
4. 在「运行工作流」选择打开企业微信、读取姓名、首个会话或批量消息。发送类工作流直接正式执行，请先核对消息和接收范围；完成后可导出处理数量和出错对象。

手机只读取 AutoJs6 系统无障碍节点，不截图，不调用图像模型，也不需要模型 API Key。每次先收起通知栏、返回桌面，再打开企业微信；页面切换、临时缺少控件或发送回查会持续等待，可手动停止。坐标异常、同名歧义、错误会话、已有草稿或账号验证仍会停止。

标题不接受省略号补全或删除数字前缀；只允许完整名称及群成员数后缀。发送回读使用同一原生消息行里的正文与唯一右侧头像，收到的同文消息不能作为成功回执。无法确认时停止，不重发；仍不把发送端 UI 观察等同于网络送达。

文字通过企业微信原生编辑控件写入并完整回读。已有草稿保留；连接变化或未知结果停止，不自动重写或重发。分类处理从企业微信会话分类列表直接打开目标，不为每个会话重新执行全局搜索。运行期间临时启用前台服务与屏幕唤醒锁，结束或失败时释放本次开启的资源；用户手动锁屏仍会停止操作。

手机必须保持解锁，并启用 AutoJs6 无障碍服务。普通微信手机工作流已移除，目录和离线包只发布企业微信业务包。

若消息来自 HTTP，手机必须能访问该接口；手机上的 127.0.0.1 指手机本身，电脑本机网关需要 USB 端口映射，断开电脑即不可用。分类中的「全部」指界面当前可完整枚举的列表；旧定时快照保留原范围，旧测试任务停用后需重新创建。

本包复用的定义由 scripts/mobile-scripts.mjs 从桌面 workflows/ 生成；不手工维护另一份业务流程。配置与 HTTP 鉴权引用位于包自己的 data 目录，升级不替换；「导出上次运行结果」包含全部目标状态，不包含鉴权值。已有启动器仍可安装和更新本包。

共享 IO 工厂通过 `require('./io.js')(por)` 创建，真实入口加载与旧凭据解密有独立回归测试。为读取已有企业微信密文，继续使用历史 Keystore alias `com.por.autojs6.wechat.credentials.v1`；该兼容标识不代表支持普通微信。不要清空 `credentials.json`、删除密钥或卸载 AutoJs6 来处理升级问题。

桌面端的「使用指引 → 手机独立运行」提供官方下载入口、启动脚本与离线工作流包保存，保存后传到手机导入即可。文件来自当前安装的桌面版本；新脚本继续由手机启动器从 Registry 检查更新。

## 手机独立定时执行（预览）

1. 重新导入最新版商店 `bootstrap.js`，更新「企业微信手机工作流」。已有配置、凭据和日志保留。
2. 在工作流「运行 / 配置」先保存消息、接收对象、HTTP 与前后置请求，再选择「新建定时任务」。选择具体工作流、五段 Cron 和 IANA 时区，预览接下来三次时间后保存。
3. 回到商店「更多 → 开启手机定时执行」。共用当前脚本引擎的 AutoJs6 无障碍服务和前台运行服务，切换页面后继续检查任务；保持手机解锁，运行期间屏幕保持唤醒。
4. 「更多 → 定时任务」可查看详情与上次结果、修改名称和时间、启停、立即执行或删除。立即执行保留计划时间；暂停只停止之后的触发。需要停止整个会话时选择「停止后续定时执行」，当前任务结束后释放唤醒锁。

每个任务固定保存时的脚本版本、配置和加密凭据引用；商店更新不改变快照，修改业务配置后需重新创建该任务。删除工作流会暂停关联任务，并保留它们引用的代码；重新安装后可手动启用。计划位于商店私有目录的 `schedules.json`，快照位于 `schedules/<ID>/<修订>.json`，调试导出包含计划状态而不包含配置快照。

从 56 或更旧版本升级到 58 后，普通运行使用新包，已有手机定时快照仍使用旧代码。要采用本轮入口、标题校验和消息方向修复，应停用旧任务，并在新包中重新创建任务；不要把“已更新业务包”误认为旧快照已自动修复。

调度按手机本机时钟每秒检查，正常触发容许 10 秒延迟；超过宽限、上一轮未结束或手机被另一工作流占用时跳过。分发前先保存已消费游标，失败、异常退出和结果不明均不自动重发。手机与桌面使用相同五段语法：`*`、数字、范围、列表、步长、月份/星期英文缩写；日期和星期都受限时采用 OR。夏令时不存在的时刻跳过，回拨重复时刻只取第一次。

定时入口使用持续运行的商店会话，不再请求截图。关闭脚本、重启手机、手动锁屏、关闭无障碍服务或系统收回宿主后，需要返回商店重新开启；恢复时只计算未来时间，不补发错过的消息。系统限制仍可能延迟或终止会话，前台服务和唤醒锁不等于后台永久保活。

## 你如何写脚本

```text
mobile-workflows/
  registry.json                    # 生成的目录，不能手工改摘要
  offline-bundle.json              # 生成的离线包
  your-script/
    workflow.json                  # 名称、版本、入口和最低运行环境
    src/
      main.js
      lib/helper.js                # 可选的依赖文件
```

`workflow.json`：

```json
{
  "schemaVersion": 1,
  "id": "your-script",
  "name": "我的手机脚本",
  "version": "1.0.0",
  "versionCode": 1,
  "minLauncher": 1,
  "minAutoJs6": "6.7.0",
  "description": "说明此脚本会做什么",
  "entry": "main.js"
}
```

`src/main.js` 使用同步 CommonJS 入口：

```js
module.exports = function (por) {
  var config = por.readConfig();
  // 在此编写业务操作，可使用 AutoJs6 API。
  por.log('开始处理', { version: por.version });
  config.lastVersion = por.version;
  por.saveConfig(config);
};
```

可用的 `por` 字段：`id`、`version`、`versionCode`、`runId`、`dataDir`；方法：`readConfig()`、`saveConfig(object)`、`log(message, details)`、`recordResult(object)`。协议 2 还提供 `readLastResult()`，读取同来源、分支和脚本的上一条保留结果；旧记录可从商店导出诊断。相对 `require('./lib/helper.js')` 从当前版本目录加载。入口不能返回 Promise；创建线程时，必须先等待其结束再返回。当前不支持脱离入口生命周期的后台线程、异步 UI 脚本或独立子引擎管理。脚本是受信任的作者代码，拥有 AutoJs6 权限，不是沙箱。

新版商店还提供可选 `por.recordResult(object)`，原子保存本次运行的结构化结果，上限 2 MiB；可重复写入进度，最终结果应包含完成状态。结果会随「更多 → 导出最近运行日志」一起导出，企业微信套件用它保存处理数量和出错对象。兼容旧启动器的脚本先判断方法是否存在；旧入口继续保留套件自己的运行结果和导出方式。不要把接口密钥或鉴权头放进结果。

商店为支持定时的包提供可选 `por.schedules`：`save({name,cron,timezone,enabled}, {workflowId,dryRun})` 固定当前包与已保存配置，`preview(cron,timezone)` 返回未来三次 epoch 毫秒，`formatTime(epoch,timezone)` 格式化指定时区。定时入口收到 `por.execution={workflowId,dryRun}`，必须直接运行对应业务核心，不显示配置/发送确认菜单、不保存新配置。已有入口通过是否存在该字段兼容；宿主仍同步等待入口结束。

## 发布一个新版本

1. 修改 `src/` 中的脚本；增加 `workflow.json` 的 `versionCode`，同时更新展示用 `version`。比较新旧版本以 `versionCode` 为准，拒绝降级和同版本替换不同内容。
2. 在仓库根目录执行：

   ```sh
   pnpm mobile:bundle
   pnpm test:mobile
   pnpm mobile:check
   ```

3. 提交并推送脚本源码、`mobile-workflows/registry.json`、`mobile-workflows/offline-bundle.json` 和生成的 `mobile/autojs6/bootstrap.js`。客户已导入的旧启动器可以直接更新业务脚本，不必重新导入生成的新文件。

发布工具会生成每个文件的 SHA-256 与字节数，检查 JS 语法和路径，并要求已有包内容变更时递增 `versionCode`。CI 检查生成文件是否过期并运行更新回归测试。

不需要创建新的桌面版本或覆盖现有 GitHub Release。手机通过 GitHub API 先锁定分支的单个提交，再从该提交下载目录和全部文件，避免混合两个提交的代码。

SHA-256 用于发现下载损坏和内容不一致，不证明脚本行为安全；只有你配置并信任的仓库才能用来分发脚本。GitHub 下载失败、令牌失效或限流时不会移除当前版本。

## 离线更新与 PC 传输

`pnpm mobile:bundle` 同时生成：

- `deliverables/PorAuto-AutoJs6-bootstrap.js`：可直接导入手机的工作流商店，约几十 KiB，包含安全测试示例。
- `deliverables/PorAuto-mobile-scripts.json`：自包含离线脚本包。PC 将此文件传到手机后，在商店选择「更多 → 导入本地工作流包」，输入实际文件路径；校验规则与在线安装相同。它不是 APK，不需要安装或解压。

离线包支持多文件和相对依赖，使用 Base64 表示字节；整包上限 10 MiB。在线目录最多 32 个脚本，每个脚本最多 128 个文件、总计 10 MiB，单个文件最多 2 MiB。路径不接受绝对路径、`..`、反斜杠、大小写重复或 Windows 保留名称。PC 图形化一键安装宿主/同步脚本入口和 PC→AutoJs6 任务通信不在本轮实现范围。

## 更新、配置和日志怎样保存

数据保存在 AutoJs6 的应用私有目录 `files/por-auto-mobile/`：

```text
settings.json
operation.lock
sources/<来源摘要>/
  state.json
  catalog.json
  versions/<脚本ID>-<版本号>-<内容摘要>/
  config/<脚本ID>.json
  data/<脚本ID>/
runs/<运行ID>/
  summary.json
  events.jsonl
  result.json                    # 新版商店的结构化结果（可选）
schedules.json                   # 手机计划、消费游标与最近状态
schedules/<任务ID>/<修订>.json     # 固定包与配置快照，不放入调试导出
```

完整下载先写临时目录，校验所有文件后改名为独立版本目录，最后原子替换安装状态文件。当前状态写入失败时旧状态仍保留；残留的完整版本可在下次检查时复用。业务配置、数据和日志不在脚本版本目录里，更新不覆盖它们。

任务与更新使用同一个跨启动器文件锁，不会同时执行；脚本文件不原地覆盖。当前入口必须同步完成。历史仅保留最近 200 条，超出后删除最旧记录；成功仅保存简要结果和处理数量，失败额外保留最近 32 条诊断事件与出错对象，常规读取不反复写日志。任务失败不自动重发消息。宿主被强行停止可能留下未完成记录，导出时标为中断；不会自动恢复这些任务。升级手机业务包后，重新导入最新版启动器才能启用宿主的日志精简与保留上限。

「更多 → 导出最近运行日志」生成最近 10 次运行的 JSON，包含来源、脚本版本、内容摘要、步骤日志和错误，不包含仓库令牌。每次运行最多保存 500 条脚本日志，超出时记录截断提示；日志文件本身保留在本机，不自动删除。导出文件写入宿主的外部私有目录 `por-auto-exports/`，随后尝试交由系统查看器打开。

不要卸载 AutoJs6 来升级，否则应用私有数据可能丢失。正常覆盖升级与本业务脚本更新是两条独立流程。升级 AutoJs6 的能力由官方宿主管理；如果未来业务脚本需要更高 `minLauncher`，需重新导入新版固定启动器，现有私有数据目录保持不变。

## 验证边界

当前 `pnpm test:mobile` 共 42 项通过，覆盖版本切换、离线运行、网络失败、摘要不符、下载中断、状态写入失败、配置保留、并发互斥、凭据不落盘、未完成记录和路径攻击。新增回归实际加载发布包入口与 IO 模块，并用历史 alias 的 AES-GCM 密文验证解密；也验证重复发送动作在 Hook/设备操作前被拒绝、相似/省略标题被拒绝，以及收发方向和长消息。

上述入口、加密和节点测试使用确定边界的模拟环境，不等于 AutoJs6 真机或 Android Keystore 的本轮验收。当前包 58 尚未做新的手机正式发送和长时间定时验收；完整范围见 [代码审查修复记录](../outputs/2026-10-22-review-fixes.md)。

基础启动器已在全新 Android 14 / API 34 模拟器、官方 AutoJs6 6.7.0 上验证：单文件导入、相对依赖与中文输出、GitHub 在线下载与摘要校验、离线 v1→v2 升级、运行次数跨版本保留、JSON 日志导出和令牌输入框取消。新增业务包还在 vivo X21 / Android 9 上验证了 Keystore 加密、接口绑定、HTTP 参数/鉴权/中文正文/字段解析及禁止跳转；控制器测试覆盖四个企业微信工作流、1000 个模拟目标、预演清理、旧草稿保护和不确定发送停止。模拟目标不代表 1000 个真机消息已验收。
